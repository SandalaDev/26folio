## Command reference and glossary

All `os` commands below use the prefix `bash scripts/os.sh`. Run them from the product root. The workflow chapters explain prerequisites and expected results; this index helps you find the right operation once you know your intent.

The following are standalone scripts, not `os` subcommands:

- `bash setup.sh`: initialize local hooks, dependency evidence and generated pages after export or clone.
- `bash scripts/scaffold-project.sh TARGET --ref REF --profile core|frontend`: export from the template checkout.
- `bash scripts/update-from-template.sh --from SOURCE --ref REF --dry-run`: preview while in the target product; use the new template's wrapper for older products.
- `bash scripts/new-task.sh epic ID "title"` or `task ID "title" EPIC RISK`: create planning skeletons.
- `bash scripts/branch.sh start EPIC`: create/resume the repository helper's feature branch.
- `bash scripts/branch.sh base|guard|sync-dev`: inspect the base, check the branch or attempt base synchronization.
- `bash scripts/branch.sh cleanup BRANCH`: delete only an ancestry-verified merged branch, including an attempted remote deletion.
- `bash scripts/branch.sh promote`: print legacy trunk-dev promotion guidance; it does not execute a deployment.
- `bash scripts/skills.sh validate`: check portable skill metadata.
- `bash scripts/intake.sh`: compatibility entry point into the current interview workflow.

### Glossary

**Template checkout:** the OS source repository used to export or update products. **Machinery:** reusable commands, instructions, skills and renderers. **Seed:** clean initial project records supplied only when scaffolding. **Product repository:** an independent project with its own intent and history.

**Charter:** why the project exists and what success means. **Roadmap:** projected work and release scope. **Epic:** a meaningful deliverable. **Task:** a bounded implementation contract. **RC:** release candidate. **Baseline:** the frozen approved scope against which change can be measured.

**Harness:** the tool running the coding agent. **Provider:** the service supplying model inference. **Control surface:** the app or interface through which work is controlled. **Session:** one recorded working interval. **Coordinator:** the agent owning the shared project session. **Worker:** an isolated agent returning a bounded result.

**Digest:** a content fingerprint used to detect changed answers or evidence. **Receipt:** a saved record of an operation, not an invoice or proof of human identity. **Coverage:** the portion of relevant observations actually known. **Allocation:** the explicit project share of a subscription distributed over eligible observed work.
